# セキュリティの現状と、確認すべきこと

**このAPIは公開されている。** 何が守っていて、何が守っていないかを明示する。

## 何が門番なのか

ウェブAPIキーは**認証情報ではない**。「どのFirebaseプロジェクトか」を示す宛先で、
ブラウザに配る以上どうせ公開される。**これを隠すことをセキュリティの前提にしない。**

実際に GPU への到達を止めているのは、次の1段だけ。

```
① キーで匿名アカウントを作る        誰でもできる
② API がIDトークンを検証            ①ができれば通る
③ uid が許可リストにあるか          ★ここだけが門番★  → 無ければ 403
④ 回数の上限                        ③を通った人への制限
```

**①②は関門ではない。** キーを持っている人は素通りする。

### 確認済みのこと

| | 結果 |
|---|---|
| 許可リストが読めないとき | **全員 403（fail-closed）** |
| 許可リストの置き場 | 専用バケット。APIは**読み取り権限のみ** |
| バケットの公開権限 | 無し。`public_access_prevention` 有効 |
| `uniform_bucket_level_access` | 全バケットで有効（オブジェクト単位のACLが無効） |
| 他人のジョブ | 署名付きURL発行**前**に所有者を検証し、404 |
| `job_id` の形式 | 入口で検証 |
| プロジェクトで有効なAPI | run / artifactregistry / storage / billing / iam / iamcredentials のみ |

## キーが漏れたら何が起きるか

| | できるか |
|---|---|
| GPU を起動する | **✗** 許可リストで403 |
| バケットのデータを読む | **✗** 公開権限なし |
| **匿名アカウントを無制限に作る** | **✓** |
| **API層に 401 / 403 の負荷をかける** | **✓**（CPUのみ・最大3インスタンスなので被害は限定的） |
| ユーザー列挙・パスワードリセットのスパム | 有効なプロバイダ次第 |
| 他の課金APIを叩く | キーの制限次第 |

## ⚠️ Firebase の設定は Terraform 管理外

**リポジトリからは確認できない。** コンソールとAPIで設定されているため、
以下はこのファイルを読んでも分からない。定期的に実機から確認すること。

### 確認する5点

```bash
P=project-db31f07b-2895-48b8-8bb

# ① ② キーの制限（restrictions が空なら無制限）
gcloud services api-keys list --project=$P --format=json | python3 -m json.tool

# ③ 有効な認証プロバイダ（匿名だけになっているか）
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://identitytoolkit.googleapis.com/admin/v2/projects/$P/config" | python3 -m json.tool

# ④ Firestore / Storage を使っていないなら空のはず
gcloud firestore databases list --project=$P

# 有効なAPIが増えていないか
gcloud services list --enabled --project=$P
```

### 入れておくべき設定

| # | 設定 | 効果 |
|---|---|---|
| 1 | **HTTPリファラー制限** を `kmykprn.github.io/*` に | casual な悪用を止める。**ただしブラウザ以外からは偽装できるので、門ではなく段差** |
| 2 | **API制限** を Identity Toolkit と Token Service だけに | 他の課金APIへの流用を防ぐ |
| 3 | **identitytoolkit のクォータを絞る** | アカウント量産の被害が上限で止まる。**既定は大きいので見落としやすい** |
| 4 | 使っていない**認証プロバイダを無効化** | 匿名だけにすればパスワードリセットのスパムが原理的に起きない |

## localhost の扱い

**既定では許可しない。** `allowed_origins` は本番のオリジンだけにしてある。

開発中にローカルから実APIを叩く必要が出たときだけ、`terraform.tfvars`
（gitignore 済み）に足して apply し、**用が済んだら戻す**。

tfvars に書けばリポジトリには残らないので、消し忘れても次に誰かが
apply したときに既定へ戻る。

## 補足: API は認証プロバイダを見ていない

`verify_id_token` はトークンの署名・期限・発行元プロジェクトを検証するが、
**どのプロバイダでログインしたかは見ていない**。匿名以外を有効化すると、
そのトークンも②を通る（③で止まるので実害はない）。

「匿名だけ」をコードで強制したくなったら、`decoded["firebase"]["sign_in_provider"]`
を見る。商用化で本登録を必須にするときは、ここが判定の場所になる。

## 製品版にするとき

`ENFORCE_ALLOWLIST=false` にすると③が消える。**そのとき残るのは①②だけ、
つまり「キーを持っている人は全員通る」**。1日10回の制限も、匿名アカウントを
100個作れば1000回（約39,000円）で意味を持たない。

**許可リストを外すのと App Check を入れるのは、同時でなければならない。**
片方だけ動かすと穴が開く。
